# Phase 9 terminal families and final result export

A terminal network family is a hierarchy node for which the configured edge
definition, resolution search, split acceptance, and stability criterion found
no further credible subdivision. It is not automatically a reconciled
evolutionary family.

```bash
ogprofiler export --run run/
```

The default command writes only four bounded exchange tables under `results/`:

```text
families.tsv
members.tsv
hierarchy.tsv
events.tsv
export-manifest.json
```

## Stable family IDs

`canonical-terminal-membership-rank-v1` orders families by their canonical
`(species_id, original_id)` membership tuples and assigns zero-padded IDs such
as `OG000000000`. The result is independent of component traversal, hierarchy
row order, and terminal-membership row order. IDs are deterministic within the
prepared dataset and clustering result; changing membership may change ranks.

Singleton connected components enter the same tables as one-member terminal
families with `terminal_reason=SINGLETON` and
`network_event=SPECIES_SPECIFIC`. Export validates that terminal memberships
form an exact partition of prepared proteins and that hierarchy and event node
sets agree.

The export manifest records input and output checksums, the family-ID algorithm,
row counts, and a membership hash per family. A second identical invocation
checksum-verifies and reuses all result tables; corruption or changed upstream
artifacts triggers reconstruction.

## Opt-in FASTA and graph output

No per-family FASTA files are generated by default. Select one or more families:

```bash
ogprofiler export --run run/ --family-fasta OG000000123
```

Exporting every family requires the explicit `--all-family-fasta` switch. This
avoids creating very large numbers of small files accidentally.

Component graphs are also explicit and local in scope:

```bash
ogprofiler export graph --run run/ --component 123 --format graphml
```

GraphML is generated from the requested component partition rather than from a
global in-memory graph.
